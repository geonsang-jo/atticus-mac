# 한국어 Mac 비서 — 첫 버전 설계안

작성일: 2026-11-23
상태: 사용자 승인 완료. 개인 계정 포크에서 구현 및 검증한다.

## 사용 상황과 목표

사용자는 윈도우에서 게임하고, 맥에서는 YouTube를 재생하면서 여러 개발 세션과 테스트를 실행한다. 키보드는 윈도우에 연결되어 있다. 맥에 연결된 마이크(내장 마이크 포함)를 통해 비서를 부르고, 한국어로 조작하고, 작업 결과를 음성으로 받는다.

가장 중요한 인수 조건은 **앱의 최초 권한 설정이 끝난 뒤, 키보드·마우스 없이 호출어로 요청을 시작하고 처리 후 다시 호출어를 기다리는 것**이다.

## 기반과 작업 위치

- 기반: SaarthurR/atticus-mac v2.0.1, ec26aaa3ace49cc4140e4dffd0395c1fc57ad8a9.
- 권장 GitHub 소유자: 개인 계정 geonsang-jo. 기존 로그인 상태를 전역 변경하지 않고 해당 계정의 인증을 명시적으로 사용한다.
- 프로젝트 위치: 사용자 새 프로젝트 경로 지침에 따라 $HOME/TOY/toss-in-app/atticus-mac. Documents는 프로젝트 주 작업 폴더로 사용하지 않는다.
- upstream 원격과 MIT 고지를 보존하며, 기존 herdr 저장소는 변경하지 않는다.

## 검토한 접근

1. **Apple 한국어 호출어 + Apple 한국어 요청 인식(권장)**: 현재 맥에서 ko-KR 온디바이스 호출어 인식을 지원하고, SpeechTranscriber/DictationTranscriber의 ko_KR 모델도 설치되어 있음을 API로 확인했다. 기존 음성 수명 관리를 재사용할 수 있다.
2. **Whisper를 상시 인식에 사용**: 혼합 언어와 모델 선택에 유리하나, 현재 whisper-server가 설치되어 있지 않고 추가 설치와 자원 사용 검증이 필요하다. 첫 버전에서는 선택형 요청 인식 대안으로 유지한다.

기기 API 조회는 실제 발화 정확도나 오탐률을 검증한 결과가 아니다.

## 1. 한국어 호출어

- 기본 호출어 제안은 **헤이 아티**이며 설정에서 변경 가능하다.
- 첫 버전의 명시적 사용 흐름은 **호출어 → 짧은 응답음 → 한국어 요청 → 짧은 응답 → 호출어 대기**다. 한 호흡으로 호출어와 명령을 붙여 말하는 기능은 첫 인수 범위에 넣지 않는다.
- UI 언어와 별도로 음성/호출어 언어를 ko-KR로 지정한다. 한국어를 선택했는데 영어 인식으로 조용히 돌아가지 않는다.
- YouTube 음성이 일반 명령으로 들어오지 않도록, 기존의 답변 직후 자동 후속 입력은 기본 해제한다. 모든 새 요청에 호출어가 필요하다.
- 자신의 TTS·안내음 재생 중에는 호출어 인식을 멈추고 재생 후 복귀한다. 첫 버전은 낭독 중 음성 끼어들기를 약속하지 않는다.
- 권한·마이크 연결·인식 엔진 실패는 실제 상태로 표시하고, 자동 복구하며, 중복 요청을 실행하지 않는다.
- 최초 설정에서 마이크·음성 인식 권한을 요청하고, 맥에서 사용할 입력 장치를 선택할 수 있다.

## 2. 한국어 YouTube 조작

첫 지원 브라우저는 사용자 환경에 맞춰 Aside다. Python adapter가 고정된 스크립트와 검증된 인자만 Aside CLI의 REPL에 전달한다. 명령마다 LLM을 호출하거나 임의 shell/JS를 생성하지 않는다.

지원 요청:

- 유튜브 열어 / 유튜브에서 재즈 검색해.
- 영상 멈춰 / 계속 재생해.
- 소리 꺼 / 소리 켜 / 볼륨 30퍼센트로 해.
- 10초 앞으로 / 10초 뒤로.
- 지금 뭐 틀어져 있어?

확정된 전사만 실행한다. 재생/정지는 토글 대신 명시적 상태 설정을 사용하고 숫자 범위는 검증한다. 부정형 요청이나 지원하지 않는 문장은 임의로 실행하지 않는다.

YouTube 영상 탭이 하나면 그 탭을 사용한다. 여러 개면 이전에 명시적으로 선택한 대상 또는 유일하게 재생 중인 탭을 식별하고, 여전히 모호하면 영상 제목을 읽어 음성으로 선택받는다. 실행 전후 target ID·URL·영상 ID와 실제 재생 상태를 확인한다.

전체 화면, 다음 추천 영상 선택, 다른 브라우저 지원은 첫 범위에서 제외한다. 실제 브라우저 검증은 mcp__aside__repl만 사용한다.

## 3. 개발 세션과 테스트 상태

### herdr 세션

- 기존 hc events --json의 snapshot과 후속 이벤트를 읽는 adapter를 별도 모듈로 둔다.
- 사용 중 / 입력 필요 / 작업 완료 / 오류 / 연결 상태 확인 불가를 구분한다.
- 완료 판단은 화면 배지가 아니라 세션 identity, raw status와 turn 경계에 근거한다. 차단·오류를 성공으로 간주하지 않는다.
- 평소에는 상태 metadata만 관찰한다. 사용자가 감시를 맡긴 세션이 완료되면, 정확히 매칭된 해당 작업의 마지막 답변만 제한적으로 읽어 요약한다. 매칭이 불확실하면 요약을 추측하지 않는다.
- 재연결·중복 이벤트로 완료 알림을 반복하지 않는다. 여러 세션 중 대상이 모호하면 이름을 읽어 선택받는다.
- 감시와 테스트 실행은 별도 작업으로 유지해 기다리는 동안에도 호출어와 다른 요청이 동작한다. 탭·세션 선택 역시 호출어와 음성 응답으로 마칠 수 있어야 한다.

지원 요청 예:

- 개발 세션들 지금 뭐 하고 있어?
- herdr 세션 끝나면 알려줘.
- 그 세션 결과 확인해줘.
- 감시 그만해.

### 테스트

- 에이전트 작업 완료와 테스트 성공을 구분한다.
- 직접 확인한 종료 코드가 있을 때만 테스트 성공/실패를 확정한다. 에이전트 답변에만 근거하면 그 출처를 밝혀 안내한다.
- 첫 버전은 설정에 등록한 프로젝트 테스트 명령을 추적 실행할 수 있게 하며, 실행 ID·작업 폴더·시작 시각·PID·종료 코드·signal·timeout·로그를 보관한다. 이 경로로 실행한 테스트는 음성으로 시작·상태 확인·완료 알림을 받을 수 있다.
- 이미 다른 곳에서 실행되어 종료 코드를 확보할 수 없는 테스트는 확인 가능한 실행 상태만 보고한다.
- 모니터링 중 자동 재실행·자동 수정·세션 중단은 하지 않는다.

결과 안내는 기본 한두 문장으로 짧게 한다. 예: “herdr 세션 작업이 끝났어요. 에이전트는 테스트가 통과했다고 보고했어요.” 또는 “등록한 테스트가 종료 코드 1로 실패했어요.”

## 모듈 경계

- 기존 Swift 앱: 한국어 locale, 호출어 수명 관리, 설정, 짧은 한국어 음성 응답.
- Korean command parser: 한국어 원문을 검증된 YouTube/session/test intent로 변환하는 순수 모듈.
- Aside media adapter: 브라우저 대상 식별, 제한된 동작, 실제 결과 receipt.
- Session observer: herdr 이벤트 reducer, 세션 identity, 감시 등록과 완료 알림.
- Test tracker: 등록된 테스트 실행과 결과 기록.
- 기존 atticus.py/build.sh: 새 모듈 연결·번들링에 필요한 변경만 적용.

## 검증과 완료 조건

1. ko-KR 설정, 한글 호출어 정규화, 인식 결과/취소/중복 이벤트 처리를 단위 테스트한다.
2. 한국어 명령·부정형·제한 숫자·모호한 탭·닫힌 탭·영상 교체를 테스트한다.
3. 녹화된 herdr 이벤트 fixture로 초기 idle, busy→done, blocked/error, 재연결, 이벤트 중복, identity 교체를 검증한다.
4. 테스트 fixture 프로세스의 exit 0/nonzero/signal/timeout을 정확히 구분한다.
5. 전체 Xcode 26 도구체인을 명령별 DEVELOPER_DIR로 선택해 Swift 검사와 빌드를 수행한다. 시스템 전역 Xcode 선택은 바꾸지 않는다.
6. Aside MCP로 실제 YouTube 상태와 조작 결과를 확인한다.
7. 설치 후 사용자의 실제 발화로 호출어→명령→응답→호출어 대기를 확인한다. YouTube 재생 중의 오작동과 반복 사용, 탭·세션 음성 선택, 작업 감시 중 추가 호출, 잠자기/깨우기 후 복구도 확인한다.

자동 테스트와 합성 음성만 통과한 상태를 실제 호출어 검증 완료로 보고하지 않는다. 필요한 macOS 권한과 실제 발화 검증은 앱이 준비된 시점에 안내한다.
